# Скрипты — менеджер CI/CD-переменных GitLab

## 📋 Обзор

В папке `scripts/` лежит один скрипт — **`gitlab_copy_env.sh`**. Это интерактивный менеджер CI/CD-переменных GitLab через REST API. Решает две задачи:

1. **Копирование** переменных из одного environment-скоупа в другой (например, `testing` → `production`).
2. **Загрузка** переменных из локальных `.env`-файлов в нужный environment-скоуп.

Это вспомогательный инструмент к [environment-scoped переменным](./08-ci-cd.md), которые использует пайплайн: при заведении нового окружения или нового проекта он избавляет от ручного перебивания десятков переменных в UI.

> 🔗 Контекст: пайплайн (`prepare_env`) объявляет `environment: { action: prepare }`, чтобы GitLab подставлял **значения секретов для нужного окружения**. Этот скрипт как раз наполняет такие environment-scoped переменные.

## 🧰 Требования

- **bash** (совместим с bash 3, т.е. работает и на macOS — вместо `declare -A` используется `python3`);
- **python3** — парсинг JSON/`.env` и сборка тел запросов;
- **curl** — обращения к GitLab API;
- **Personal/Project Access Token** со scope **`api`** (нужен и на чтение, и на запись переменных).

## ⚙️ Конфигурация (`gitlab_vars.conf`)

Скрипт ищет конфиг рядом с собой (`scripts/gitlab_vars.conf`) или в текущем каталоге (`./gitlab_vars.conf`). Если не найден — используются (пустые) дефолты, и скрипт упадёт с подсказкой.

Создайте `gitlab_vars.conf`:

```bash
GITLAB_URL="https://git.snpdev.ru"
PROJECT_ID="803"                     # числовой ID проекта (Settings → General)
TOKEN="glpat-xxxxxxxxxxxxxxxxxxxx"   # PAT/Project Access Token со scope=api
ENV_FILES=".env @strapi/.env"        # какие .env читать в режиме 2 (по умолчанию эти)
```

Обязательны `GITLAB_URL`, `PROJECT_ID`, `TOKEN` — без них скрипт выходит с ошибкой.

> ⚠️ **Безопасность:** `gitlab_vars.conf` содержит токен — добавьте его в `.gitignore` и **не коммитьте**.

## ▶️ Запуск

```bash
cd scripts
./gitlab_copy_env.sh
```

Появится меню выбора режима:

```

║        GitLab CI/CD Variables Manager           ║
╠══════════════════════════════════════════════════╣
║  1. Скопировать из существующего environment    ║
║  2. Загрузить из .env файлов репозитория        ║
╚══════════════════════════════════════════════════╝
```

## 🔁 Режим 1 — копирование между environment'ами

Поток работы:

1. Запрашивает **все** переменные проекта (`GET /variables?per_page=100`).
2. Показывает список доступных environment-скоупов с количеством переменных:
   ```
   Доступные environments:
     • *           (12 переменных)
     • testing     (24 переменных)
     • production  (24 переменных)
   ```
3. Спрашивает **источник** (`SOURCE_ENV`) и **назначение** (`TARGET_ENV`).
4. Фильтрует переменные источника и сохраняет их в файл `gitlab_vars_<SOURCE_ENV>.json` (в текущем каталоге).
5. Показывает предпросмотр (маскированные значения как `[MASKED]`, остальные — первые 40 символов).
6. После подтверждения (`y/N`) загружает каждую переменную в `TARGET_ENV`, **сохраняя** её `masked`/`protected`/`variable_type`.
7. Печатает итог: создано / обновлено / ошибок.

> 📄 GitLab API возвращает **значения** в том числе маскированных переменных (токен имеет scope `api`), поэтому копирование работает. Это же означает, что файл `gitlab_vars_<env>.json` содержит секреты в открытом виде — **удалите его после** или держите вне git.

## 📥 Режим 2 — загрузка из `.env`-файлов

Поток работы:

1. Спрашивает целевой environment (`TARGET_ENV`).
2. Парсит файлы из `ENV_FILES` (по умолчанию `.env` и `@strapi/.env`) на python:
   - пропускает пустые строки и комментарии (`#`);
   - матчит `KEY=VALUE` (`^[A-Za-z_][A-Za-z0-9_]*=...`);
   - снимает обрамляющие кавычки (`"` или `'`);
   - при дубликатах ключа **побеждает последний** (источник запоминается для предпросмотра).
3. Показывает таблицу найденных переменных с источником и усечённым значением.
4. После подтверждения загружает каждую как `masked=false`, `protected=false`, `variable_type=env_var`.
5. Печатает итог.

> ⚠️ В этом режиме переменные грузятся **немаскированными** — значения будут видны в UI. Не используйте его для боевых секретов «как есть», если важна маскировка (для секретов предпочтительнее режим 1, где `masked` сохраняется).

## 🧩 Логика загрузки одной переменной (`upload_var`)

Самая нетривиальная часть — устойчивое создание/обновление с откатами. Тела запросов собираются через `python3` (корректный JSON-escape значений). Алгоритм:

```
POST /variables
 ├─ 201 → создана ✅                       (return 0)
 └─ 400 (уже существует) →
      PUT /variables/{key}?filter[environment_scope]={env}
       ├─ 200 → обновлена ↺                (return 1)
       └─ 404 →
            POST без masked
             ├─ 201 → создана (no mask) ✅  (return 0)
             └─ иначе → ошибка ✗            (return 2)
```

Плюс ветка для «неожиданных» HTTP-кодов: пробует по очереди `PUT` → `POST` без masked → `PUT` без masked, и только потом сдаётся.

Зачем откаты на `no mask`: GitLab отклоняет маскирование значений, не удовлетворяющих требованиям маскировки (длина/набор символов). Тогда переменная создаётся **немаскированной**, чтобы загрузка не падала целиком.

Коды возврата используются для подсчёта итогов: `0` — создано, `1` — обновлено, `2` — ошибка.

### Используемые эндпоинты

| Функция | Запрос |
|---|---|
| `do_post` | `POST {API}/variables` |
| `do_put` | `PUT {API}/variables/{key}?filter[environment_scope]={env}` (`--globoff` — чтобы curl не трактовал `[]`) |
| список | `GET {API}/variables?per_page=100` |

где `API = {GITLAB_URL}/api/v4/projects/{PROJECT_ID}`, заголовок `PRIVATE-TOKEN: {TOKEN}`.

## ⚠️ Важные замечания

- **Токен** должен иметь scope `api` и роль ≥ Maintainer (создание/изменение CI-переменных).
- **`gitlab_vars.conf`** (токен) и **`gitlab_vars_<env>.json`** (значения секретов) — в `.gitignore`, не коммитить.
- Внутренний комментарий в шапке скрипта называет его `gitlab_vars.sh` — это просто старое имя, фактический файл `scripts/gitlab_copy_env.sh`.
- `environment_scope` — это строка скоупа (`testing`, `staging`, `production`, `*`). Должна совпадать с `ENV_NAME`, который пайплайн использует для подстановки секретов (см. [08-ci-cd.md](./08-ci-cd.md)).
- Скрипт **идемпотентен**: повторный запуск обновляет существующие переменные (`PUT`), а не плодит дубликаты.
